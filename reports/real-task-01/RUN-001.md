## Exact defect and diagnosis

The original assignment constructed a conflict ID using a double-quoted f-string containing a multiline replacement expression, dictionary literals with the same quote style, and a canonical hash slice:

```python
conflict["conflict_id"] = f"REENTRY-CONFLICT-{canonical_hash({
    "kind": AUTHORITY_IMPLEMENTATION_DRIFT,
    "drift_conflict_key": stable_key,
})[:16]}"
```

The closing quote exists. The failure is a **Python grammar compatibility issue**, not evidence that the file was truncated or a quote was accidentally deleted. Python 3.12's expanded f-string grammar accepts constructs that Python 3.11 rejects here. On the actual supported environment, rejection occurs during parsing, even if that code path would never execute during startup.

The smallest correction replaces interpolation with literal-prefix concatenation while retaining the dictionary contents and hash slice:

```python
conflict["conflict_id"] = "REENTRY-CONFLICT-" + canonical_hash({
    "kind": AUTHORITY_IMPLEMENTATION_DRIFT,
    "drift_conflict_key": stable_key,
})[:16]
```

This changes syntax, not the intended conflict identity, deduplication key, classification, or model-call policy. Source reference: [reentry implementation](../../hivo/reentry.py); published mechanism test: [authority drift tests](../../tests/test_authority_drift.py).
