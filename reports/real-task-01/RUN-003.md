## Confirmed defect: object overlap loses predicate scope

The requirements are compatible: displaying a current/best score says what the UI shows; preserving the maximum and never replacing it with a lower score constrains storage/update behavior. The latter does not prohibit displaying that score.

The read-only diagnostic reproduction identified shared tokens `best` and `score`. Original [requirements.py](../../hivo/requirements.py), `_conflict_evidence`, compared positive/negative target token intersections, allowing a negation about replacing a value to be interpreted as a prohibition on that value. Predicate/action and negation scope were lost. This explains the observed false conflict; it does not establish that every one of the three emitted conflicts has identical detailed semantics.

The false gate was the first genuine capability blocker in the initial baseline sequence. It was not Context Sufficiency, Mutation Grounding, a Worker failure, or Behavioral Verification: none of those stages had been reached.

## Why the rewrite is withheld

Broader publication review later found genuine contradictions that the rewrite missed, including `Encrypt stored records.` versus `Do not encrypt stored records.` The original detector reported one conflict; the proposed detector reported zero. Logging and compression predicates exposed the same regression. The bounded action vocabulary did not cover those predicates.

Consequently, the nine passing tests demonstrate selected scoped behavior only. They do not justify representing the rewrite as a verified general fix. Both source and experimental test remain local for review; neither is silently included in the runtime PR. The original false positive therefore remains unresolved in the published code. [Fixes and validation](FIXES-AND-VALIDATION.md) gives the broader counterexamples.
