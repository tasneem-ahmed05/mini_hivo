[Contribution scope](README.md) · [Evidence and novelty](EVIDENCE-AND-NOVELTY-MAP.md)

## F1: distinguish six different integration claims

PR #2 establishes which execution stages Coin Courier reached. The additional question here is which experimental mechanisms those stages actually validate. Use this sequence, with separate evidence at every transition:

```text
implementation exists → policy is available → policy selected
→ runtime route activates it → mechanism exercised → behavior verified
```

Neither implication from implementation to activation, nor from authorization to behavior, is automatic. Source presence is checked against executable base `f842fb8fb6e63e3064891d26ee0b24981e55c847`, not against an unmerged teammate branch. The [history](../../docs/EXPERIMENT_HISTORY.md) checkpoints for Experiments 1–17 are ancestors of that base. The subsequent Experiment 18 additions relative to `4d1760b` modify five report/index files only. Availability below means relevant code or diagnostic harness exists; it does not assert that every known defect is fixed.

The saved CLI selected `current_recursive`, mission advice `strict`, verification classification `field_scoped`, and `current` for Worker progress, grounding, locator, verification environment/surface, receipts, integration targets and semantic evidence. Defaults are explicit in [argument parsing](../../mini.py#L29635-L29666); launch provenance is already published in [PR #2's setup](https://github.com/tasneem-ahmed05/mini_hivo/blob/1e233845b3e9d26b10bb66238ec13a00f108356e/reports/real-task-01/EXPERIMENT-SETUP.md).

## Coverage classification

**Verified** applies only to a directly observed, scoped expectation. **Failed** means an observed mismatch with an expectation, not failure of every component in an experiment. **Not Reached** covers an unselected variant or an unexecuted boundary. **Not Observable** means this task/evidence cannot assess the experimental claim. **Pending Fix** identifies an unresolved diagnosed integration defect; it is not an execution-success result.

Rows refer to the relevant experimental treatment. Common upstream code can run while the treatment remains untested. Existing tests are evidence of implementation intent and coverage scope; they were inspected, not executed or counted as E2E success in this investigation.

## Integration conclusions added by this matrix

1. **The baseline inherits research code without constituting a selected integrated policy.** Several policies are mutually exclusive alternatives: semantic `compatible`/`monotonic`/`strict`, grounding variants, and planning routes cannot all be selected simultaneously. Mechanism owners must name and support a coherent combination.
2. **Greenfield versus approved-contract execution is a substantive coverage boundary.** Earlier execution harnesses often inject frozen approved contracts; this free-request greenfield run did not demonstrate activation of the same wrappers. Passing those fixtures cannot close the newly identified route gap.
3. **Selected does not mean exercised.** Experiment 17's flag is the clearest instance: it was selected, yet application verification was never reached.
4. **Authorization is not grounding or behavior.** Context/impact transitions are observed; no mutation tool or application oracle was exercised. Existing tests and earlier experiments remain valuable, but Coin Courier cannot certify their downstream integration yet.

The detailed execution history and acceptance status remain in [PR #2](https://github.com/tasneem-ahmed05/mini_hivo/blob/1e233845b3e9d26b10bb66238ec13a00f108356e/reports/real-task-01/README.md), not repeated here. The matrix's untested boundaries must not be counted as failed experiments or combined into a success percentage.
